Guitar Hero III — UI Redesign

Modernising navigation and interaction without losing the rock identity that made the original iconic.

ContributionConcept & UI Design
TypeSelf-directed
ToolsFigma
DeliverableInteractive prototype

Independent conceptual exercise. Non-commercial, with no affiliation to or endorsement by the rights holders of the brands referenced.

Context

Guitar Hero III is a rhythm game whose interface was built for a console generation with different conventions and different expectations of feedback. The visual identity still holds up. The interaction layer around it does not.

I took it as a self-directed exercise in a constraint I find genuinely interesting: modernise an interface without flattening the personality that made it memorable in the first place. Most "redesigns" solve legibility by erasing character. I wanted the opposite.

Problem

I audited the original interface and isolated four concrete points of friction:

  • The loading screen is static. Dead time that builds no anticipation for what follows.
  • The main menu has weak visual hierarchy. Nothing signals which option matters most, so every option costs the same to evaluate.
  • The pause menu presents unprioritised information, slowing down access at exactly the moment the player is mid-song and impatient.
  • The HUD is overloaded, competing for attention with the one thing that actually matters: the note track.

That last one is the real problem. In a rhythm game, every pixel that pulls the eye away from the note track is a design failure with a measurable cost in player performance.

Process

Visual research

The moodboard drew on concert posters, and on the typography and palettes of rock bands — Motörhead, Iron Maiden — plus graphic design from punk and garage flyers. The intent was to anchor the system in an authentic visual language of rock rather than a generic video-game aesthetic.

Process note: ambient backgrounds in the moodboard were generated with AI (Gemini) as atmospheric reference only. The UI system, hierarchy and interaction design are my own work.

Structure before surface

Hand-drawn wireframes settled the structure before any visual decision was made: main menu hierarchy, HUD information grouping (note count, rock meter, song progress) and the pause menu layout. Deciding hierarchy while already looking at colour is how you end up rationalising an aesthetic choice as a functional one.

Design decisions

Main menu

Simplified, with hierarchy carried by colour and by typography borrowed from concert posters. Key options are identifiable at a glance rather than after reading the full list.

Loading screen

Rebuilt to create anticipation through animation and classic rock visual references, replacing the original's dead air. Loading time is unavoidable; spending it on nothing is not.

Pause menu

Structured after guitar tablature — a form the audience already reads fluently. Clear hierarchy so pausing doesn't break immersion, and so returning to play is the fastest available action.

HUD

Stripped to essentials. Note count and rock meter grouped to one side so they occupy a single glance rather than two; a song progress bar added to give temporal context without adding clutter. Grouping related information is what buys the screen space back.

Result

A complete, coherent UI system across four screens — loading, main menu, pause and HUD — navigable as a functional prototype in Figma.
